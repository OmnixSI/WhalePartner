# B4 实现假设

- 当前唯一目标是用户本机；SQLite 路径沿用 `APP_DB_PATH`，向量模型和 Mem0 文件沿用 `MEMORY_DIR`。
- 不更换现有 TypeScript、Node 或 Mem0 技术栈，不复刻 Mastra/Memvid 实现。
- 旧聊天没有会话字段，迁移时每个角色的旧消息作为一个“历史聊天”会话，原消息 ID 和时间不变。
- 默认输入预算取 24K token 估算值。由于不同供应商 tokenizer 不同，以 CJK 字符、符号和拉丁文本长度作保守估算；可配置预算，不将估算描述为精确 token 数。
- 通过显式会话创建开始新聊天；历史会话保留在本机并可重新打开。
- Mem0 负责本地语义召回；SQLite FTS5 是原始聊天的词项召回和来源权威。B4 事实与经历可从 SQLite 重建向量索引；没有 SQLite 来源的 B3 记忆仍依赖旧向量库。
- 会话、聊天片段和由聊天学到的角色内容按角色过滤；用户事实以及视频、网页和日记经历仍可供角色共用。
- 用户事实只有在用户自己的消息中提取；助手输出、自动日记和角色反思属于生成内容，不作为用户事实的证据。
- 任务持久化解决进程重启后的可恢复性；这不是多进程分布式任务队列，也不实现跨设备同步。
- 上下文 Token 数是模型无关的保守估算，不是供应商 tokenizer 的精确计数。
- 任务队列只协调本机单个 API 进程，不实现多进程或跨设备的分布式执行。
