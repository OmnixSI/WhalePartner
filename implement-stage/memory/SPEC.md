# B4 本地长期记忆与长会话上下文

## 目标

在现有 WhalePartner TypeScript/Node + SQLite 服务中，让每个角色拥有可持续的会话上下文和可检索的本地经历。原始聊天、带证据的结构化事实和经历档案留在本机 SQLite；事实由模型提炼后写回 SQLite，Mem0 与本地中文向量模型负责可重建的语义召回；旧经历可通过全文检索和向量召回重新进入聊天。

## 设计

- 以本机 `APP_DB_PATH` SQLite 为聊天、会话、原始事件、上下文观察和记忆处理任务的权威数据源。
- 为会话和角色建立边界。旧消息迁移到各角色的一个“历史聊天”会话，现有记录不删除。用户事实及非聊天视频/网页/日记经历继续共享；聊天片段和聊天来源学习内容只召回给所属角色。
- 对用户及助手消息建立本地 FTS5 索引。中文采用二元词项；每条命中返回角色、会话、消息时间和原文，便于核对来源。
- 本机检索覆盖关键词、语义和显式时间范围（例如去年、上个月、某年）；没有可靠证据时不作为事实注入。向量索引不可用时，SQLite FTS 与已有结构化记录继续支持本地检索。
- 为会话保留 Observer 滚动摘要和已覆盖消息游标。上下文始终由受保护的人格提示、相关长期记忆、会话摘要、旧消息证据和近期原文组成，并使用保守字符估算控制输入预算。
- 对每轮已完成的聊天持久化排队：模型从用户消息提炼带逐字证据的事实并写入 SQLite；完整轮次作为可追溯的会话经历保存到本地，Mem0 只负责向量索引；Observer 更新会话摘要。任务失败保留在 SQLite 中，下次启动或有新对话时重试。
- 不把 AI 日记或助手生成的反思写成用户事实；不自动改写角色人格核心。
- 客户端仅增加本地会话选择/新建入口，调用当前本地 API；不引入云端服务或同步协议。

## 主要接口变化

- `POST /api/chat` 接受可选 `sessionId`，并在 SSE `done` 中返回其会话标识。
- `GET /api/chat/sessions?character=...` 列出本机该角色会话。
- `POST /api/chat/sessions` 新建本机会话。
- `GET /api/chat/history` 接受可选 `sessionId`；旧客户端无该参数时仍读取兼容的默认会话。
- `GET /api/memories` 返回既有 Mem0 记忆与可用来源信息；记忆数据仍由原有 API 查看和删除。

## 验收

- 既有 SQLite 消息升级后仍可读，且查询结果归属于角色历史会话。
- 同会话可加载滚动摘要和近期原文；按早期聊天关键词检索能返回原始消息与时间来源。
- 跨会话语义检索包含已有事实和已索引的会话经历，不再仅注入最近三条经历。
- 记忆任务在应用重启后可从本机 SQLite 恢复；失败任务不会阻塞聊天。
- 提示上下文按输入预算打包，保留完整角色人格和最近原文；用模型无关的保守估算，不声称无限上下文或精确 tokenizer 计数。
- 记忆和原始聊天不上传到云数据库；视频与日记继续走现有本地接口。向量库缺失时从 B4 SQLite 事实和经历档案重建索引。

## 验证

使用 API 与客户端类型检查、客户端 production build，以及内存 SQLite 合成记录验证长会话原文召回、角色过滤和估算上下文预算。未运行需要外部模型的语义召回或事实提取检查。
