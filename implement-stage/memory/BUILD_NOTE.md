# B4 构建记录

## 实现

- `APP_DB_PATH` 中的 SQLite 现在保存会话边界、完整消息、带逐字来源的事实版本、经历档案、Observer 滚动记录和可恢复的记忆任务。既有聊天迁移为各角色的“历史聊天”会话。
- 中文 FTS5 二元索引与显式时间范围检索覆盖旧消息、事实和经历。当前会话保留近期原文；跨会话回忆附带消息时间、会话和来源证据。
- 事实、外部经历、聊天片段、学习记录和角色近况分开处理。记忆提取与向量写入通过 SQLite 任务恢复；向量不可用时，本地 FTS 与结构化事实仍可用于聊天。
- Observer 逐步压缩较早会话；上下文管理器为当轮资料、观察、事实、经历、学习内容、角色近况、归档证据和近期消息分配估算预算，并始终保留人格核心与当前问题。
- 最近经历仅在用户询问近期活动或共同经历时补充；其他问题只使用关键词、时间或语义匹配的记录。
- `store.ts` 作为薄门面；数据库迁移、会话、事实、经历、索引、观察和任务各有独立仓库。HTTP 路由按聊天、历史、记忆、视频、日记和账号拆分；Mem0 的索引适配与懒加载分别维护。
- 客户端支持新建、切换本机聊天会话；记忆页显示事实来源和事实版本，并能删除事实及经历。清空聊天会同时清理聊天事实、观察和聊天来源学习记录。
- 全文索引行与完成标记在事务内一起写入；启动重建会修复标记或 FTS 行缺失的记录。会话历史加载使用请求序号，较早的响应不会覆盖当前选择。

## 验证

- Node `v26.13.0`，符合仓库 `>=26 <27` 要求。
- API：`tsc --noEmit -p tsconfig.json` 通过。
- 客户端：`tsc --noEmit` 通过；Vite production build 通过。
- `git diff --check` 通过。
- 本机 FTS 验收使用内存 SQLite 和 2501 条合成消息、100 次查询：找回约 2400 条消息之前的目标内容；角色过滤通过。查询 p50 `0.364 ms`、p95 `0.442 ms`。
- 启动恢复回归用例模拟消息 FTS 行与标记不同步、以及 FTS 行缺失；重复运行重建后旧消息仍可检索。
- 合成 provider 与内存 SQLite 验证了未启用向量存储时的写入：事实保留逐字消息来源，聊天经历保留会话关系，视频经历保留在本地，向量索引状态待建，任务队列完成；向量召回也未带入其他角色的学习记录。
- 上下文预算验收以 8000 token 估算上限和较大的合成资料输入执行：打包结果估算 `7519/8000`，当前问题保留。

## 剩余限制

- 延迟结果来自内存 SQLite 合成数据，不代表用户磁盘数据库，也不覆盖本地 Embedding 的语义召回耗时。真实 tokenizer 仍可能与字符估算有偏差。
- 未调用外部模型验证事实提取或向量语义召回。只存在于旧 B3 Mem0 向量库、没有 B4 SQLite 来源档案的条目，在向量文件丢失时仍无法重建。
- 客户端 bundle 成功构建；当前 JavaScript 主 chunk 为约 `1.08 MB`，Vite 提示超过 `900 kB` 的拆分建议。
