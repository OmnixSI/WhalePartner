# 每日综合日记

综合日记按共享本机日期，把当天与用户发生的真实交流整理成一篇第一人称记录。切换角色不会切换日记库；手动生成时使用当前人格，定时生成使用默认人格。旧版视频队列并行存在，旧数据继续可读、重试，综合日记作为日记页的主要内容。

## 素材与边界

日记读取所有人格当天的聊天、已处理视频/网页、学习记录、会话观察和共享近况。没有视频也可以仅凭聊天生成。无有效素材时返回空结果，不调用模型。

模型使用当前角色的人格设定，只写基于素材的经历与主观感受。用户的情绪、行为和共同事件必须能在来源中找到依据；日记正文不会作为新聊天原文或事实来源。生成提示只包含去重后的来源条目，并在素材过多时按时间跨度抽样，覆盖当天早晚与不同来源，同时限制输入长度。

## 本机数据与版本

`daily_journals` 为共享日期保存一个稳定标识和当前版本号。`daily_journal_revisions` 保留正文、模型标识、写入时间和该版引用的来源；`daily_journal_sources` 关联来源 ID 及可能的聊天会话。既有按角色保存的日记不删除，合并列表按日期展示最近更新的一篇。源数据和日记经历保存在应用 SQLite，向量条目只是可重建的检索索引。

共享日记来源 ID 为 `journal:shared:<YYYY-MM-DD>`。这同一 ID 用于全文/向量经历归档，避免每次生成都新增一条可召回记忆。视频和网页正文按稳定内容来源去重；每次在聊天中打开时会保存独立的发生时间和来源消息，因此同一天重复查看也会作为单独经历进入日记。日记来源查询排除日记自身，因此日记不会循环成为自己的材料。日记详情可以展开来源、定位原聊天消息或打开原链接，并查看旧版本。

自动定时和手动生成共享同一套按日期去重逻辑；同一 API 进程内同时触发只会执行一个生成任务。素材来源没有变化时，重复计划任务返回当前版本。显式重新生成会增加版本，不覆盖旧正文。删除来源会话时，引用该会话的综合日记记录及其派生经历一并清除。

`daily_journal_tasks` 持久化角色、本机日期、阶段、重试次数和日记正文是否已写入 SQLite，不复制来源文本。日记修订与 `body_saved` 标记在同一 SQLite 事务提交。API 若在正文保存前停止，启动后会重新读取仍有效的来源并生成；正文已保存但经历归档未完成时，启动后复用已保存正文，不再调用模型。向量写入继续由现有经历索引队列重试。被删除的聊天会话不会从任务状态中复活。

## 运行方式

API 进程按主机本地时区运行 `JOURNAL_CRON`，默认每日 20:30；旧版视频处理任务单独使用 `DIARY_CRON`，默认每日 20:00。API 启动时恢复未完成的综合日记任务；若当天计划时间已错过，会为当天补跑一次，不会为 API 离线期间的每个历史日期批量补写。Tauri 客户端和 API 是独立进程，定时器由 API 进程持有；API 停止期间不会触发计划任务。用户可以在日记页手动生成/更新当天日记。配置见 [API 文档](API.md)。

聊天输入的 macOS 听写和日记模型生成是两条独立链路：听写由系统写入普通文本框，日记仍由当前配置的聊天模型生成。

## 日记页读取与展示

日记页按当前周、月或年向 `GET /api/journals` 请求共享日记，同时读取 `GET /api/diary` 保留的旧版视频日记队列。综合日记按本机 `localDate` 解析，不将日期字符串转换成 UTC 时间戳；同一日期只展示一篇当前日记，正文修订仍留在 SQLite。周视图按日期倒序展示；月视图以手帐式日期网格标出真实主题与记录数，选择日期后查看当天的综合日记和旧版视频日记；返回日历会保留月份和所选日期。年视图汇总各月记录数并可直接进入月份，不展开全年正文。日期主题取自记录标题或正文首句，长主题在格内收敛，完整正文仍在详情中查看。

页面上的“请她写今天的”调用 `POST /api/journals/generate`，成功后重新读取列表并翻到今天。读取失败显示错误和重试入口，不显示成空日记；重新进入页面会重新加载所选日期范围。测试只使用临时 SQLite 和模拟 provider，业务验收使用原有 `apps/api/.local/` 数据库。
