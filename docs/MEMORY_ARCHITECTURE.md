# 本地长期记忆与会话上下文

WhalePartner 的记忆数据保存在用户本机。现有 TypeScript/Node 服务使用应用 SQLite 文件保存原始聊天、会话、观察、结构化事实、经历档案和处理队列；Mem0 使用本地中文向量模型做语义召回。记忆索引是派生数据，聊天原文和结构化记录留在 SQLite。

这套链路不引入云端数据库或跨设备同步。模型推理仍使用当前配置的提供方；如果配置的是云模型，组装后的对话上下文会发送给该模型。用户事实以及视频、网页、日记经历可以由各角色共用；会话、聊天经历和从聊天学到的内容按角色隔离。`MEMORY=off` 关闭 Mem0 与语义索引，不关闭 SQLite 事实、经历、会话观察或关键词检索。

## 数据层

| 数据 | 本机存储 | 用途 |
|---|---|---|
| 用户和角色消息 | `messages` | 完整聊天原文；保留角色、会话、时间、消息 ID |
| 会话 | `chat_sessions` | 会话边界、角色、标题和最近活动时间 |
| 会话观察 | `session_observations` | Observer 滚动压缩较早对话，并记录覆盖的消息范围 |
| 事实版本 | `memory_facts` | 用户明确表达的事实、偏好、计划和关系，含置信度、重要度和有效时间 |
| 事实来源 | `memory_fact_sources` | 将结构化事实关联到用户原文、会话和时间 |
| 经历档案 | `memory_experiences` | 聊天片段、视频/网页摘要、日记和学习记录；稳定 `source_id` 可去重 |
| 处理队列 | `memory_jobs` 与经历索引状态 | 模型提取、摘要和向量写入的断点恢复 |
| 全文索引 | `message_search`、`fact_search`、`experience_search` | FTS5 检索；原文仍以普通 SQLite 表为准 |
| 向量索引 | `MEMORY_DIR/vectors.db` | Mem0 + 本地 BGE 中文 Embedding 的语义召回 |

既有 `messages` 数据迁移到各角色的“历史聊天”会话，消息内容和原始 ID 保留。

## 记忆写入

1. 用户消息先写入 SQLite，并更新本地 FTS 索引。
2. 模型回复成功后，在同一 SQLite 文件中追加一个可恢复的记忆任务。
3. Observer 只读取用户原文提取候选事实；候选必须带有可在原文中逐字找到的证据。只有明确修正或变化的事实才关闭上一版本，并以新消息时间作为新版本 `valid_from`。
4. 当前轮次作为聊天经历写入 SQLite，并尝试写入本地 Mem0 向量索引。视频、网页、日记和学习经历也先保存在经历档案，再更新向量索引。
5. Observer 持续更新会话摘要；原消息不会因压缩而删除。
6. 现有 Mem0 记忆提取仍运行，旧 B3 数据保持可读；B4 的结构化事实额外保留了版本和直接来源。

处理状态和下一次重试时间都在本机数据库中。服务启动时恢复中断任务；向量索引失败时仍保留 SQLite 原文，后续启动或聊天会再次尝试。缺失本地 `vectors.db` 时，B4 SQLite 事实和经历会重置索引游标并重新向量化。`GET /api/health` 返回待处理任务、重试任务和待向量化的事实/经历数量。

## 查找与上下文

- **FTS5**：中文文本先转换为二元词项，精确查找消息、事实和经历；返回结果带时间、会话和消息来源。查询含“去年/上个月/某年”等时间范围时，同时使用 SQLite 时间索引筛选原文、经历和事实有效期。
- **向量召回**：本地 BGE 在 Mem0 中搜索事实、旧聊天片段以及视频/日记/网页经历。
- **时间与事实状态**：事实按有效时间保留当前版和被取代的旧版。旧数据不会因年龄自动从相关召回中删除。
- **会话上下文**：当前会话的滚动观察、相关历史原文、长期记忆与最近原文一起装入模型。模型从原文和来源证据中核对具体回忆。
- **上下文预算**：`CHAT_CONTEXT_TOKENS` 默认 32K，约 8K 留给回复和模型结构；输入使用字符级保守估算，不等同于任一提供方的精确 tokenizer。完整角色设定优先保留；记忆、摘要、旧消息按相关性取舍，最近原文使用剩余预算。

用户可在聊天页新建会话并切换同一角色的历史会话。切换会话只改变当前原文上下文；共享的用户事实和非聊天经历仍可跨角色检索，聊天档案和聊天来源学习记录不会串到其他角色。

## 代码模块

| 模块 | 职责 |
|---|---|
| `apps/api/src/store.ts` | 对聊天服务提供稳定存储门面 |
| `apps/api/src/store/` | SQLite 建库/旧消息迁移、会话、事实、经历、观察、任务和 FTS 索引仓库 |
| `apps/api/src/memory/facts.ts`、`observer.ts`、`jobs.ts` | 用户事实候选、会话观察及可恢复任务处理 |
| `apps/api/src/memory/archive.ts` | 经历先写 SQLite，再尽力更新可重建的向量索引 |
| `apps/api/src/memory/recall.ts`、`context.ts` | 本地混合召回、来源核对、预算估算和上下文打包 |
| `apps/api/src/memory/mem0-store.ts`、`mem0.ts` | 本地向量存储适配及懒加载 |
| `apps/api/src/chat-materials.ts`、`chat-background.ts` | 视频/网页经历写入、角色学习和近况反思 |
| `apps/api/src/routes/` | 按聊天、历史、记忆、视频、日记和账号分开的 HTTP 入口 |

公共存储由小型门面组合领域仓库；记忆检索、上下文构建和 HTTP 路由分开维护，避免将数据访问和流程逻辑堆入单一文件。

## 查看与删除

`GET /api/memories` 合并本机结构化事实、SQLite 经历档案和已有 Mem0 数据。`local:` 与 `local-exp:` 标识 SQLite 事实和经历；事实显示状态、有效时间、置信度和来源原文。删除单条事实会一并删除其来源关联；删除外部经历会同时清理本地档案和对应向量。

“清空聊天记录”会删除全部聊天消息、会话、观察、角色近况、聊天事实、聊天经历和来源为聊天的学习记录；视频、日记、网页经历及由这些内容学到的记录保留。事实和经历详情可在记忆页逐条删除。

## 当前限制

- FTS5 的中文二元词项适合实体名和短句检索；只有语义相近、没有共同词项的历史内容依赖本地向量索引。
- 本地 B4 事实与经历有 SQLite 权威副本，可在缺失向量库时重新索引；较早 B3 Mem0 中没有对应 SQLite 来源记录的条目仍以既有本地向量库为准。
- 结构化事实来自模型抽取，证据要求与用户原文逐字匹配；抽取不成功时原始消息仍可搜索，不会伪造一条已确认事实。
- token 数使用模型无关估算，仍可能与某个提供方实际 tokenizer 有偏差。
- SQLite、Mem0 向量和模型缓存当前保存在本机文件中，没有数据库加密或端到端加密。
